# Playbooks

* [Cut a release](release.md) - How a release is made: Conventional Commits on `main`, an `## [Unreleased]` changelog section, the `v0.0.0` baseline tag that keeps the first release at 0.1.0, and `semantic-release.yml`, which tags the release and dispatches Knowledge Release to attach `schema-<tag>-in-toto.yaml` once `KNOWLEDGE_RELEASE_ENABLED` is true.
* [Regenerate and test after a schema change](regenerate-and-test.md) - How to change the schema and check it: `uv sync --group dev`, edit the modules under `src/in_toto_linkml/schema/`, then `just lint`, `just gen-project`, `just gen-doc`, `just lokf-adapt` and `just test`, and the pre-commit hooks before a pull request.
* [Update the upstream pins](update-upstream-pins.md) - What to do when the weekly upstream watch reports that in-toto/attestation released again, changed or dropped a pinned file, or moved the pinned tag, that the copy drifted, or that a check could not finish: replace the copy whole from one release, move the pins in `scripts/check_upstream_release.py` and the schema header, and run the tests.
* [Validate data against the schema](validate-data.md) - How to validate in-toto data with `linkml-validate` before loading it into the generated Python models, which check less: the dataclasses check no pattern and read an empty required list as a missing one, the Pydantic models miss the timestamp's pattern, and neither checks a class's conditions. No check covers a repeated key, a mismatched predicate type or URI normalization.
* [Knowledge sources map](knowledge-sources.md) - The librarian's scrape map: every repository location this bundle derives concepts from, the concepts each yields, how to re-check each on a refresh run, and the paths left out on purpose.
